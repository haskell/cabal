synopsis: "`cabal sdist <pkg>` works when run inside the package directory"

`cabal sdist <pkgname>` failed with `[Cabal-7151] The component library cannot be
packaged for distribution on its own` when run inside the package directory,
because a bare package name resolves to the package's primary library component.
Any target selector referring to a component (or a module or file within a
component) of a local package now selects that package, so `cabal sdist <pkg>`,
`cabal sdist <pkg>:lib:<pkg>` and similar forms package the containing package.
Explicit component-kind filters such as `cabal sdist tests` still fail with
`[Cabal-7151]`. Multiple selectors resolving to the same package (e.g.
`cabal sdist a a-tests`) now produce a single archive per package instead of
duplicates, and `cabal sdist a a-tests --output-dir -` writes one tarball to
standard output rather than failing with `[Cabal-7152]`.

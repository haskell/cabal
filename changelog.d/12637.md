---
synopsis: Warn when conflicting `index-state` values resolve to different index entries
packages: [cabal-install]
prs: 12639
issues: 12637
---

`index-state` can be set in `cabal.project` and the files it imports, in
`cabal.project.freeze` and `cabal.project.local`, and on the command line with
`--index-state`. The value read last wins, but this happened silently.

`cabal` now warns, at normal verbosity, when the `index-state` values given in
more than one place resolve to different entries of a package index. The
warning lists where each value was set and the index entry it resolves to, so
it is clear which one is used. Values that differ but resolve to the same index
entry do not cause a warning.

At `-v2`, the message saying that a historical index state was explicitly
requested now names where the value came from, for example `cabal.project.local`
or the command line, instead of only saying "command line / project
configuration".

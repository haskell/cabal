---
synopsis: "`cabal get -s` no longer moves the cloned git branch to the tag"
packages: [cabal-install]
issues: 10278
prs: 0000
---

When a package's `source-repository` has a `tag:`, `cabal get --source-repository`
used to clone the repository and then run `git reset --hard <tag>`, which moved
the cloned branch back to the tag, so it no longer matched the remote. It now
checks out the tag as a detached `HEAD` instead, leaving the branch as it is on
the remote.

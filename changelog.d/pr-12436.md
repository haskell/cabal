---
synopsis: Use Text instead of String in data BuildInfo and class HasBuildInfo
packages: [Cabal-syntax]
prs: 12436
---

Moving towards using sensible string types in Cabal, we change the remaining `String` fields
of `data BuildInfo` to contain `Text` to return `Text` instead of `String`. Simultenaously,
we change lens in `class HasBuildInfo` in the same fashion.

Namely, `cppOptions`, `asmOptions`, `cmmOptions`, `ccOptions`, `cxxOptions`, `jsppOptions`, `ldOptions`,
`hsc2hsOptions`, `extraLibs`, `extraLibsStatic`, `extraGHCiLibs`, `extraBundledLibs`,
`extraLibFlavours` and `extraDynLibFlavours` are now `[Text]` instead of `[String]`.
Further, `options`, `profOptions`, `sharedOptions`, `profSharedOptions`, `staticOptions`
are now `PerCompilerFlavor [Text]` instead of `PerCompilerFlavor [String]` (and same for
helper functions `hcOptions`, `hcProfOptions`, `hcSharedOptions`, `hcProfSharedOptions` and `hcStaticOptions`).
Finally, `customFieldsBI` are now `[(Text, Text)]` instead of `[(String, String)]`.

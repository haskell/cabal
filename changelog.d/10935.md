`cabal vendor` copies the source tarballs of a project's dependencies, as
selected by the solver for the current project configuration, into a directory
laid out as a `file+noindex` package repository (`<pkgid>.tar.gz` plus the
revised `<pkgid>.cabal` file from the package index), so that the project can
be built without network access. Dependencies from `source-repository-package`
stanzas are vendored as source distributions of their checkouts; local
packages are skipped. The directory defaults to `vendor` in the project root
(`--output-directory` changes it), and the command prints the `repository`
and `active-repositories` stanza to add to the project file. Package names
can be given to vendor only some dependencies, `--prune` removes package
files that the current plan no longer needs, and `--unpack` unpacks the named
packages under `vendor/src/` to work on them as local packages.

`cabal build --offline` no longer refuses packages that come from a
`file+noindex` repository, since nothing is downloaded for them; that makes
`--offline` usable with a vendored repository.

```console
$ cabal vendor
Vendored 12 packages into /home/me/proj/vendor

To build using the vendored packages, add the following to the project file
(the 'url' line must stay indented under 'repository'):

repository vendored
  url: file+noindex:vendor

active-repositories: vendored
```

QA notes: in a project with Hackage dependencies, run `cabal vendor`, add the
printed stanza to `cabal.project`, point `remote-repo-cache` at an empty
directory (or remove `~/.cache/cabal/packages`) and check that
`cabal build --offline` succeeds; `cabal vendor --dry-run` writes nothing;
`cabal vendor some-dep` vendors only that package and prints
`active-repositories: :rest, vendored:override`.

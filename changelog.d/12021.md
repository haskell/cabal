---
synopsis: Use file monitoring for pre-processor re-run checks
packages: [Cabal, cabal-install]
prs: 12021
---
This fixes a bug where pre-processors were not re-run if the build tool itself
changed, but the preprocessor input did not (see [issue
11411](https://github.com/haskell/cabal/issues/11411])). We use the existing
file monitoring infrastructure for this.

To make this possible, the `PreProcessor` data structure needed to be changed;
the previous `runPreProcessor` field has been replaced by a `getPreProcessor`,
which returns a pair of the actual preprocessor function (the equivalent of
`runPreProcessor`) and a `PreProcessorKey`. The latter captures the
preprocessor's dependencies, which indicate whether the preprocessor itself has
changed or not, and can be one of:

- `PreProcessorBuiltin`: indicates that this is a preprocessor built into GHC
  or Cabal; no checks are needed, because the only way it will change is if we
  select a different Cabal or GHC version, in which case the build will happen
  in a different location.
- `PreProcessorPrograms`: a list of configured programs that are used to
  preprocess the input. Cabal will compare paths to infer whether any of them
  have changed.
- `PreProcessorCustom`: indicates that this is a custom preprocessor
  (implemented as an arbitrary `IO` action); the string parameter should be
  picked such that it changes exactly when the custom preprocessor changes, but
  how that is achieved is up to the user.

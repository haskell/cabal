---
synopsis: Fix shallow clone failure when a project uses one repository twice
packages: [cabal-install]
prs: 11921
issues: 12296
---

A `cabal.project` with two `source-repository-package` stanzas for the same
git repository at different commits failed to build with
`fatal: reference repository '...' is shallow`.

Cabal passes the first checkout of a repository as `git clone --reference` for
every later checkout of that same repository, so that they share one object
store. But git refuses `git clone --reference` when the reference repository is
shallow, and these checkouts are made with `git clone --depth=1`, so the second
stanza always failed. The reference is now only passed when the first checkout
is in fact not shallow — which is the case, and the only case, where it ever
worked: git ignores `--depth` when cloning from a plain local path.

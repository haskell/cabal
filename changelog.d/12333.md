---
synopsis: Use the exact tools recorded by `ghc --info`
packages: [Cabal]
prs: 12333
issues: [12332]
---

Cabal configures the toolchain programs it invokes itself (the C compiler
used by hsc2hs and for interpreting `cc-options`, `ar`, and the `ld` that
combines objects into a library for GHCi on GHCs without `--merge-objs`)
from GHC's settings file, exposed via `ghc --info`: when the recorded
command is an absolute path to an existing executable, that exact tool is
used instead of a like-named program found on the search path. A missing or
bare command falls back to a lookup by name, which is what GHC itself does.

Previously the search path was also seeded with the directory of the
recorded command, and for a bare command name that directory is `.` — the
directory the build runs in — so a like-named executable there would be
picked up. It no longer is.

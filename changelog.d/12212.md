---
synopsis: Fix documentation lost for re-exports across internal sub-libraries
packages: [Cabal]
prs: 12212
---

Fix a bug where `cabal haddock --haddock-for-hackage` silently dropped
documentation for identifiers re-exported through internal sub-libraries,
emitting a "Couldn't find .haddock for export" warning and showing 0%
coverage for affected modules.

The root cause was a path mismatch: during `build`, an internal
sub-library's `.haddock` interface path was registered using the
`ForDevelopment` directory naming (just `<pkgname>`), but
`haddock --haddock-for-hackage` writes the interface to the `ForHackage`
naming (`<pkgname>-<version>-docs`). Since `cabal` invokes haddock
separately per component, the main library's haddock phase still saw the
stale build-step registration and could not locate the interface file.

Two fixes are applied:

1. `inplaceInstalledPackageInfo` now takes a `HaddockTarget` parameter so
   that the haddock phase registers the correct directory naming. This
   fixes the in-memory package index when multiple targets are processed
   in a single `haddock_setupHooks` call.

2. `haddockPackagePaths` now falls back to the alternate `HaddockTarget`
   directory naming when the registered `.haddock` interface path does not
   exist. This handles the case where the in-memory index carries stale
   paths from the build phase (the common case in v2-style builds).

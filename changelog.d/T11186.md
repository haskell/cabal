---
synopsis: "Consistent lookup of `includes` and `install-includes` header files"
packages: [Cabal]
prs: 12310
issues: 11186
---

Header files named in `includes` and `install-includes` are now looked up in the
same set of directories everywhere, via the new
`Distribution.Simple.BuildPaths.includeSearchDirs`.

Previously, compilation, preprocessing with `hsc2hs`, the configure-time header
check and the installation of `install-includes` each searched a different
subset of these, so a header could be found by one and not by another. In
particular:

  - A header at the package root (without any `include-dirs`) would not be found
    when compiling C sources. `GHC` and `hsc2hs` now receive `-I<package root>` and
    `-I<component build dir>` on every invocation.

  - Generated headers placed in a component's build directory (e.g. `GHC`'s
    FFI stub headers) were not on the include path when compiling.
    Conversely, headers generated by `configure` into the package build
    directory were not found when installing `install-includes` for a
    sub-library or foreign library.

  - Absolute `include-dirs` entries were silently ignored when locating
    `install-includes` files (#11186).

---
synopsis: Build packages with MicroHs
packages: [Cabal, cabal-install]
prs: 11392
significance: significant
---

Cabal and cabal-install can now configure, build, install and register
packages with MicroHs (`mhs`, https://github.com/augustss/MicroHs), a small
Haskell compiler. Select it with `compiler: mhs` and `with-compiler: mhs` in
`cabal.project`, or with `Setup configure --mhs`.

The packages that come with mhs, such as `base`, are found through `mhs -L`.
The libraries that Cabal builds are compiled into mhs package files, which the
components depending on them preload, so that each component sees exactly the
packages it depends on. Only what simple packages need is implemented; there
is no support for Backpack, foreign libraries, profiling, shared libraries or
C sources in libraries.

The `base` of mhs is versioned like mhs itself and bundles the modules of
`bytestring`, `text`, `deepseq`, `stm`, `directory`, `process`, `hashable` and
`integer-logarithms`. So that packages written for GHC solve, Cabal presents it
as `base-4.19.1.0` and the bundled packages as installed packages of their
own, at the versions MicroCabal uses for the same purpose.

Since mhs ignores the `LANGUAGE` pragmas of the extensions it does not
implement, packages are not rejected for the extensions they declare, and
`reexported-modules` are accepted, as mhs sees all the modules of the
packages it loads, unless they rename modules, which mhs cannot do. The macros of `cabal_macros.h`, such as `MIN_VERSION_base`,
are passed to mhs as `-D` options of its preprocessor.
